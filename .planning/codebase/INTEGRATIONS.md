## Data Storage

**Databases:**
- MySQL 8.0 (`8.0.46` on the dev server, verified 2026-08-03)
  - Connection: Via `DATABASE_URL` environment variable (`mysql://` connection string)
  - Client: Prisma ORM (`@prisma/client` + `@prisma/adapter-mariadb` driver-adapter)
  - Driver Adapter: Uses `@prisma/adapter-mariadb` instead of the standard Prisma TCP connector, enabling custom connection pooling
  - **The adapter's name is not the engine.** `@prisma/adapter-mariadb` is Prisma's single driver adapter for the whole MySQL/MariaDB family — it wraps the `mariadb` npm client, which connects to MySQL servers too. This database is MySQL. Never pick a MariaDB image, service, or dialect from the package name.
  - Schema: `prisma/schema.prisma` (two models: `User` and `RefreshToken`)
  - Migrations: Managed via `npm run prisma:migrate` (dev) and Prisma Migrate on production deployment

## Authentication & Identity

**Auth Provider:**
- Custom implementation
  - Access tokens: Short-lived JWTs (15 minutes), signed with `JWT_SECRET` env var
    - Token format: Payload `{ id, email, name }`, signed via `@fastify/jwt`
    - Returned in response body (not in headers or cookies)
  - Refresh tokens: Opaque 40-byte random hex strings
    - Stored as SHA-256 hash in `refresh_tokens` DB table
    - Set as `httpOnly` cookie scoped to `/auth` path
    - Single-use: revoked immediately on rotation or logout
    - Expiry: 7 days from issuance
  - Password storage: bcrypt with 10 salt rounds (see `src/services/user.ts`)

**Routes:**
- `POST /auth/register` - Create new user account
- `POST /auth/login` - Authenticate and receive token pair
- `POST /auth/refresh` - Rotate access token using refresh token cookie
- `POST /auth/logout` - Revoke refresh token
- `GET /auth/me` - Get current user profile (requires valid access token)

## Environment Configuration

**Required env vars:**
- `DATABASE_URL` - MySQL connection string (driver-adapter format)
  - Example: `mysql://user:password@localhost:3306/smart_house`
  - Parsed and validated by Zod schema in `src/lib/env.ts`
  - Application exits if missing

- `JWT_SECRET` - Secret key for signing JWTs
  - Minimum 1 character (enforced by Zod)
  - Recommended: 32+ character random string
  - Application exits if missing

**Optional env vars:**
- `PORT` - HTTP server listen port (default: 3000)
- `HOST` - HTTP server bind address (default: 127.0.0.1)
- `LOG_LEVEL` - Fastify logger level, e.g., `debug`, `info`, `warn`, `error` (default: info)

**Secrets location:**
- Loaded from `.env` file at application startup (via `dotenv/config` in `src/lib/env.ts`)
- **Security note:** `.env` is in `.gitignore` and should never be committed
- Production deployment: env vars should be set via hosting platform (environment variable injection)

**Env validation:**
- Enforced by Zod schema at `src/lib/env.ts` — synchronous validation on import
- Invalid configuration causes immediate process exit with detailed error messages
- No partial initialization; all-or-nothing approach

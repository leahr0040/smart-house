## Directory Purposes

**prisma/:**
- Purpose: Database schema and migration management.
- Contains: `schema.prisma` data model definition; auto-generated migration files from `prisma migrate`.
- Key files: `prisma/schema.prisma` defines User and RefreshToken models.

**src/generated/:**
- Purpose: Auto-generated code (never edit manually).
- Contains: Prisma client types and query builders generated by `npx prisma generate`.
- Regenerate: Run `npm run prisma:generate` after changing `prisma/schema.prisma`.

**src/lib/:**
- Purpose: Infrastructure utilities and singletons.
- Contains: Prisma client setup, environment config.
- Access pattern: Import from `src/lib/*` throughout services and plugins.

**src/plugins/:**
- Purpose: Fastify plugins that extend the instance with decorators and middleware.
- Contains: Auth (JWT setup), error handling, HTTP helpers.
- Load order: Alphabetical; all load before routes.
- Pattern: Export default `fastify-plugin` async function.

**src/routes/:**
- Purpose: HTTP route handlers.
- Contains: Nested directories map to URL paths (e.g., `src/routes/auth/index.ts` → `/auth/*`).
- Pattern: Each file exports a `FastifyPluginAsync` with route definitions and co-located schemas.

**src/services/:**
- Purpose: Business logic isolated from HTTP.
- Contains: Database queries, password hashing, token operations.
- Constraint: Pure functions only; no Fastify types; can be reused in tests, CLI, etc.

**src/test/:**
- Purpose: Test files.
- Contains: Test runner using Node's `node:test` + `node:assert`.
- Helper: `src/test/helper.ts` provides `build()` function to spin up Fastify instance.

**src/types/:**
- Purpose: Shared TypeScript type definitions.
- Currently empty; reserved for future shared types (e.g., API response envelopes, domain models not in Prisma).

**dist/:**
- Purpose: Compiled JavaScript output.
- Generated by: `npm run build` (TypeScript → JavaScript).
- Consumed by: Tests run against `dist/` (e.g., `npm test` → `node --test dist/src/test/**/*.test.js`).

## Key File Locations

**Entry Points:**
- `src/server.ts`: Main server bootstrap; creates Fastify instance and starts listener.
- `app.ts`: Root Fastify plugin; registers plugins then routes via AutoLoad.

**Configuration:**
- `tsconfig.json`: TypeScript compiler settings (e.g., target, lib, outDir: dist).
- `prisma/schema.prisma`: Database schema and ORM model definitions.
- `src/lib/env.ts`: Environment variable parsing and validation.
- `.env`: Local environment file (create with `DATABASE_URL`, `JWT_SECRET`, etc.).

**Core Logic:**
- `src/services/user.ts`: User creation and lookup.
- `src/services/auth.ts`: Login logic (password verification).
- `src/services/refresh-token.ts`: Token generation, validation, and revocation.
- `src/routes/auth/index.ts`: Register, login, me, refresh, logout endpoints.
- `src/plugins/auth.ts`: JWT initialization and token decoration methods.

**Testing:**
- `src/test/helper.ts`: Fastify app builder for tests.
- `src/test/routes/root.test.ts`: Example test file (health check endpoint).
- Run: `npm run build && npm test` or `npm run build && node --test dist/src/test/routes/root.test.js`.

## Naming Conventions

**Files:**
- Route files: `index.ts` (exports default FastifyPluginAsync). E.g., `src/routes/auth/index.ts`.
- Schema files: `schemas.ts` (co-located with route file). E.g., `src/routes/auth/schemas.ts`.
- Service files: `[domain].ts`. E.g., `src/services/user.ts`, `src/services/auth.ts`.
- Plugin files: `[concern].ts`. E.g., `src/plugins/auth.ts`, `src/plugins/error-handler.ts`.
- Test files: `[subject].test.ts`. E.g., `src/test/routes/root.test.ts`.
- Config files: `[name].ts` (e.g., `env.ts`, `prisma.ts`).

**Directories:**
- Plural nouns for collections: `src/services/`, `src/routes/`, `src/plugins/`, `src/test/`.
- Singular nouns for scopes: `src/lib/`, `src/types/`, `src/generated/`.
- Nested directories under `src/routes/` mirror API paths. E.g., `src/routes/auth/` → `/auth/*`.

**Functions:**
- Services: Verb-noun pattern. E.g., `createUser()`, `loginUser()`, `verifyRefreshToken()`, `revokeRefreshToken()`.
- Routes: Implicit (handlers are FastifyRequestHandler). Named by HTTP method + path.
- Utilities: Descriptive. E.g., `hashToken()`, `setRefreshCookie()`.

**Variables:**
- camelCase: `request`, `reply`, `user`, `refreshToken`.
- Constants: UPPER_SNAKE_CASE. E.g., `ACCESS_TOKEN_EXPIRES_MINUTES`, `REFRESH_TOKEN_EXPIRES_DAYS`.
- Private/internal: Prefix with `_` if needed (rare; ES2020 private fields preferred in classes).

**Types:**
- Interfaces/types: PascalCase. E.g., `LoginBody`, `User`, `RefreshToken`.
- Enum-like objects: UPPER_SNAKE_CASE or PascalCase depending on use. E.g., `JWT_EXPIRY_MINUTES` or `TokenType`.
- Discriminated unions: Named after entity + state. E.g., `type LoginResult = { success: true; user: User } | { success: false; reason: string }`.

## Where to Add New Code

**New Feature (e.g., "Devices" domain):**
1. **Database model**: Add `Device` model to `prisma/schema.prisma`. Run `npx prisma migrate dev` to create migration.
2. **Service layer**: Create `src/services/device.ts` with pure functions (`createDevice()`, `getDeviceById()`, etc.).
3. **Routes**: Create `src/routes/device/index.ts` with handlers. Create `src/routes/device/schemas.ts` for validation.
4. **Tests**: Add `src/test/routes/device.test.ts` with integration tests.

**New Route under existing domain (e.g., "GET /auth/profile"):**
1. Add handler to `src/routes/auth/index.ts`.
2. Add schema to `src/routes/auth/schemas.ts`.
3. Add test to `src/test/routes/auth.test.ts` (if it doesn't exist yet).

**New Shared Utility or Library function:**
1. If HTTP-agnostic: Add to appropriate service file (e.g., token utils to `src/services/refresh-token.ts`).
2. If cross-domain: Create `src/lib/[name].ts` (e.g., `src/lib/crypto-utils.ts`).
3. Export and import where needed.

**New Fastify Plugin (e.g., rate limiter):**
1. Create `src/plugins/[concern].ts` with `export default fp(async (fastify, opts) => { ... })`.
2. AutoLoad will register it alphabetically before routes.
3. Decorate Fastify instance with new methods if needed (use `declare module 'fastify'` for TypeScript).

**New Test Suite:**
1. Create file `src/test/[subject].test.ts` following Node test runner pattern (`import { test }` + `test()` calls).
2. Use `build(t)` helper to spin up Fastify instance (see `src/test/helper.ts`).
3. Run: `npm run build && node --test dist/src/test/[subject].test.js`.

## Special Directories

**src/generated/:**
- Purpose: Prisma auto-generated client.
- Generated: By `npm run prisma:generate` or `npm run prisma:migrate`.
- Committed: Yes; required for type checking and builds.
- Edit: Never. Regenerate via Prisma CLI after schema changes.

**dist/:**
- Purpose: Compiled JavaScript.
- Generated: By `npm run build` (runs `tsc` TypeScript compiler).
- Committed: No; in `.gitignore`.
- Clean: Run `npm run build` before tests or deployment.

**prisma/migrations/:**
- Purpose: Database migration history.
- Generated: By `npx prisma migrate dev` (creates `.sql` files).
- Committed: Yes; version control for schema changes.
- Apply: Automatically on app start (with `@prisma/internals` if configured), or manually via `npm run prisma:migrate`.

**.env:**
- Purpose: Local environment variables.
- Committed: No; in `.gitignore`. Create locally.
- Required: `DATABASE_URL` (MariaDB connection string) and `JWT_SECRET`.
- Example:
  ```
  DATABASE_URL=mysql://user:password@localhost:3306/smart_house
  JWT_SECRET=your-secret-key-here
  PORT=3000
  HOST=127.0.0.1
  LOG_LEVEL=info
  ```

## Phase Goal

**As an** authenticated user, **I want to** add typed devices to my rooms, list and manage them by room and by house, and have each device start with a valid state row, **so that** my home's devices are tracked and isolated to me, ready for commands and telemetry in later phases.

<objective>
Deliver the full Device CRUD vertical slice end-to-end, including the phase's most architecturally significant piece — eager per-type state-row creation (STATE-01). TypeBox validates device_type on create (unknown → 400); the service inserts the device and its matching *_states row in one transaction via a typed deviceStateConfig; list views work by room and by house (denormalized houseId, no room join); PATCH is metadata-only (device_type immutable, no re-parenting); delete is a leaf soft-delete. Multi-tenancy (404) and auth (401) enforced on every route, with the DB-touching test suite.

Purpose: Devices are the leaves of the hierarchy and the anchor for state (Phase 6) and commands (Phase 4). Establishing the eager-state invariant now means the consumer hot path is only ever a guarded UPDATE, never a create.
Output: `src/routes/devices/{index,schemas}.ts`, `src/services/device.ts` (with `deviceStateConfig`), `src/test/routes/devices.test.ts`.
Sequence: CLAUDE.md structure-first → tests-red → implement (three tasks, three atomic commits).
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → device API | Untrusted JWT + params/body; both the device AND its parent room/house ownership must be enforced |
| service → DB | relationMode="prisma": app layer is the sole ownership enforcement point; eager state row is app-orchestrated in one transaction |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-2-D01 | Elevation of Privilege | POST /rooms/:roomPublicId/devices (nested-parent ownership bypass) | high | mitigate | createDevice resolves parent room via findFirst {publicId,userId} before insert; foreign room → 404 (test asserts) |
| T-2-D02 | Information Disclosure / EoP | GET/PATCH/DELETE /devices/:devicePublicId + by-room/by-house lists (IDOR / BOLA) | high | mitigate | Ownership-embedded where:{publicId,userId} on every device query and on the parent resolve for lists; cross-tenant → 404 not 403 (TEST-01) |
| T-2-D03 | Spoofing | All device routes without JWT | high | mitigate | preHandler: fastify.authenticate on every route; 401 asserted (TEST-08) |
| T-2-D04 | Tampering | Mass assignment — device_type change, re-parenting (room_id/house_id), client-supplied initial state, state_type/state_id | high | mitigate | PATCH schema omits deviceType + additionalProperties:false (→400); create body carries no state values; service destructures only whitelisted fields; state_type/state_id set solely by the eager-create transaction |

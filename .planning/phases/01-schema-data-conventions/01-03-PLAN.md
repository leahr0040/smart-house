<objective>
Add the complete new-domain schema — House, Room, Device, Command, CommandTarget, the four per-type state detail tables (light_states, ac_states, heater_states, sensor_states), and the append-only events table — to `prisma/schema.prisma`, then apply it as one Prisma-generated additive migration and run the full Phase 1 acceptance gate. This delivers the bulk of DATA-01 (snake_case `@map`/`@@map` on every new model), DATA-02 (denormalized `user_id` on Room/Device/Command), DATA-03 (`deleted_at` on House/Room/Device), and the schema-level foundation of DATA-04 (unique index on the deterministic `event_id`, the tuple-guard `last_event_at`/`last_event_id` columns, and the FK indexes the consumer transaction relies on).

Every value/range/vocabulary rule stays in the TypeBox app layer (later phases): NO native DB enums, CHECK constraints, or min/max here (D-06) — status/type/mode columns are plain `String`. The additive migration is pure `CREATE TABLE` on tables that have never held data, so unlike 01-01/01-02 it carries no data-loss risk and needs no hand-edit or human gate — it is applied autonomously.

Purpose: Lock the entire target schema before any entity record is created, so later phases build on stable columns and indexes.
Output: Ten new tables live; full acceptance gate (migrate + build + tests) green; Phase 1 complete.
</objective>

  <action>
Conduct the ≤10-minute spike that ROADMAP success criterion 5 requires and record it in a new file `.planning/phases/01-schema-data-conventions/01-UUID-SPIKE.md`.

The spike has two parts:
1. STORAGE DECISION (already researched — record it): document that the schema uses `String @db.Char(36) @default(uuid(7))` rather than `Bytes @db.Binary(16)`, with the RESEARCH rationale — Prisma's native `uuid(7)` generator is only valid on String fields (RESEARCH Pitfall 2, GitHub issue #11414), and BINARY(16) would force raw-SQL `UUID_TO_BIN`/`BIN_TO_UUID` of unverified MariaDB compatibility for a negligible per-row saving at this project's scale. Note that this CHAR(36) choice must carry into the Phase 7 cursor comparison (a raw parameterized `WHERE (recorded_at, event_id) > (?, ?)` tuple query — RESEARCH Pitfall 5), since CHAR(36) sorts correctly as a lexicographic string tiebreaker.
2. VERSION EVIDENCE (must observe, not assume — RESEARCH Assumptions Log A2): confirm `@default(uuid(7))` actually emits a version-7 UUID, not v4. Insert one row into any new uuid-PK table using the generated Prisma client (e.g. create a throwaway Command row via a one-off `node` script against `src/generated/prisma`, or via `npx prisma db execute` reading back a generated value), read back the `id`, and confirm the 13th hex character (the version nibble, position after the second hyphen group) is `7` — the canonical shape `xxxxxxxx-xxxx-7xxx-yxxx-xxxxxxxxxxxx`. Record the observed id string and the version-nibble check result in the spike file. If the nibble is `4`, the schema used bare `uuid()` somewhere — STOP and fix before finalizing (this is the RESEARCH Pitfall 1 hard gate). Delete the throwaway row after observing it so it does not pollute the database.

Keep the spike file short (a decision + evidence, not an essay). It is the durable record ROADMAP criterion 5 asks for.
  </action>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| additive migration SQL → live database | Additive `CREATE TABLE`s cannot destroy existing data, but malformed index/Decimal/Json DDL could fail apply — caught by `prisma migrate dev` exit code, not by `npm run build` |
| generated id ↔ ordering assumptions | The spike verifies the generator emits v7; a v4 leak here would silently break every downstream ordering guarantee |

<objective>
Hand-author the migration that renames the existing, populated `User` table to `users` and adds its `deleted_at` column — without data loss. Use `prisma migrate dev --create-only` to draft the migration, then replace Prisma's default destructive `DROP TABLE`/`CREATE TABLE` pair with an `ALTER TABLE ... RENAME`, hand-verify the SQL, and only then apply it.

Purpose: `@@map` on a model that already has a live table cannot be diffed as a rename by Prisma — it defaults to DROP+CREATE, which would silently delete every existing user and break the `refresh_tokens.user_id` linkage. This plan is the data-loss guard for DATA-01. It is `autonomous: false` because a human must inspect the generated SQL before it touches the live database.
Output: One applied migration under `prisma/migrations/` that emitted `RENAME TABLE`, leaving all existing auth rows intact.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| schema source → generated client | An error in `schema.prisma` propagates into `src/generated/prisma/` and every future query; caught by `npm run build` |
| (No runtime trust boundary this plan) | Phase 1 adds no endpoint, no request handling, no auth surface — no client→API boundary is created |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Tampering | `events.snapshot` Json column | low | accept | The snapshot stores producer payloads verbatim (D-07). No untrusted input reaches it in Phase 1 (no write path exists yet). Value-shape validation is a Phase 5/6 (worker/consumer) concern via TypeBox before persistence; documented as an accepted deferral, not a Phase 1 gap. |
| T-01-02 | Tampering | Time-ordering of event_id / last_event_id | high | mitigate | A bare `@default(uuid())` would silently emit v4, breaking the tuple-guard ordering the whole consistency model depends on. Mitigation: the `!grep '@default(uuid())'` gate in Task 2 verify blocks any bare-uuid occurrence; Plan 03 adds a live smoke-check confirming a generated id carries version nibble 7. |
| T-01-03 | Elevation of Privilege | Soft-delete columns absent/mis-typed | medium | mitigate | If `deleted_at` is missing or non-nullable, Phase 2+ ownership/soft-delete filtering cannot be enforced. Mitigation: Task 1 adds `deletedAt DateTime?` (nullable) to User; House/Room/Device get the same in Task 2; verified by grep + `npm run build`. |
</threat_model>
